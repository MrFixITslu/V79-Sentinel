# V79 Sentinel private Tailscale approver-only gateway (10 October 2026)

## Scope and current state

Acer has a one-purpose gateway bound ONLY to `127.0.0.1:8794`, running
under the unprivileged `firelion` systemd user service
`v79-sentinel-private-approver-gateway.service`.
It forwards ONLY `POST /api/v1/sentinel/service/approver/check` to the
private local NOC `127.0.0.1:8788`.
No NOC administrator endpoint, console, login, telemetry, health page,
or browser cookie is proxied. Unwanted paths and methods return 404.
Machine authentication requires HMAC signed body and strict headers,
then checks live approver identity when the NOC machine service is enabled.

The Acer device is shared with the Dell's `MrFixITslu@github`
identity. Tailscale policy configured by owner permits Dell-side
identity to reach the Acer's 100.111.143.125 TCP/443 only.
Verified from the Dell host AND Tiquet container: Acer SSH :22 and
NOC :8788 both TIME OUT; :443 was reachable by policy but refused
because no Serve listener was configured. Private DNS now resolves,
and `tailscale ping` succeeds. Current membership stays unchanged.

## Required Acer owner sudo action to enable ONLY private Serve

Run in Acer interactive terminal (privilege elevation cannot be
performed through the remote desktop security controls):

```bash
sudo tailscale serve --bg --https=443 http://127.0.0.1:8794
tailscale serve status
```

This is Tailscale **Serve**, NOT Funnel. Confirm status says private
HTTPS for this node and forwards to `http://127.0.0.1:8794`.
Do not grant permanent operator rights with `tailscale set --operator`
just for this one change.

After command: verify from both Dell host AND Docker Tiquet container
using normal TLS validation:
`https://firelion-aspire-a315-51.tailcbdd5b.ts.net`.
Expect HTTP **404** for `/`, `/healthz`, NOC dashboard/auth routes.
Signed-approver route must deny unrecognized/unsigned calls; live
human-status flag is still OFF, so no ticket approvals may be released.
Compare SHA-256 certificate details if certificate error occurs; do not
disable TLS certificate checking or install untrusted root CA silently.

- The gateway requires no private key or HMAC secret itself; only the NOC

  remain active.

## Recovery

If connection or TLS checks fail, keep live ticket dispatch OFF. A
safe stop on Acer without changing Tailscale sharing:

```bash
systemctl --user stop v79-sentinel-private-approver-gateway.service
```

When authorized to remove ONLY this dedicated Serve entry, check
`tailscale serve status` and `tailscale serve --help` first. Do not
blindly reset unrelated services or remove shared-device access.
